# Documentation Service Contract

Status: Final

Documentation Service owns journals, entries, reflections, media references, and the derived timeline. Media binaries and object-storage URLs remain owned by Media Service and are not part of M2 Documentation persistence.

Public routes are `GET/POST /journals` and `PATCH/DELETE /journals/{id}`. Resources are owner-private. Creation may include TEXT entries only through `CreateJournalEntryInput`; journal creation has no media operations and cannot create reference entries. PATCH uses stable ID-based operation arrays for entries, reflections, and media references; all operations and version checks commit atomically. Every child create and update supplies a unique non-negative position within its resulting collection; positions are compacted atomically before commit. Text entries require content and prohibit a media-reference ID. Reference entries require a stable Documentation-owned media-reference ID, prohibit text content, and require the referenced active child to belong to the same journal and have the matching media kind. `JournalMediaReference` alone persists the opaque Media Service ID; the reference grants no media access.

Reference entries are created only through PATCH. Within one PATCH, the request creates the media-reference child in `mediaOperations`, creates the reference entry in `entryOperations`, and resolves it through the media operation's request-scoped `clientReference`. Mutation phases execute deterministically as `mediaOperations`, `entryOperations`, then `reflectionOperations`, preserving array order within each phase. A client reference is unique within the request, is used only for dependency resolution, is never persisted or returned as a canonical ID, and cannot resolve forward or cyclic dependencies. Unknown, duplicate, forward-unresolvable, cyclic, inaccessible, cross-journal, or kind-mismatched references reject the complete atomic transaction.

Permission policy selection is server-controlled. Documentation Service resolves and validates the journal's policy reference and current positive version synchronously through Permission Service before creation and protected access. Public DTOs never accept or expose policy fields. Unavailable, invalid, stale, revoked, denied, or unverifiable policy state fails closed, and policy details are absent from public responses, ordinary errors, logs, and telemetry.

Deletion immediately removes the aggregate from normal behavior and uses ADR-0008 retention. No raw binary, download URL, local path, storage credential, external-provider information, restore, sharing, AI summary, AI reflection, upload, or media-processing behavior is in M2. Exact schemas and persistence are defined by OpenAPI, validation, database, and AsyncAPI documents.
